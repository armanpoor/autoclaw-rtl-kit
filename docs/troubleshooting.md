# عیب‌یابی

## پرانتزها برعکس دیده می‌شوند

پرانتز نویسهٔ خنثی است و جهت خود را از پایهٔ پاراگراف می‌گیرد. تا وقتی پایهٔ جهت راست نشود، پرانتز باز در سمت چپ جمله دیده می‌شود. راه‌حل: بستهٔ جهت‌دار، یا ایزوله‌کردن همان قطعه:

```html
<span dir="rtl">(بدون هیچ پکیج خارجی)</span>
```

## عدد و هگز وسط جمله به‌هم می‌ریزد

رشته‌های لاتین را از بدنهٔ فارسی جدا کنید. سه سطح، از بهتر به قابل قبول:

۱. بلوک کد جدا:

````markdown
ضریب مقیاس جدول زاویه جرقه:
```
0.375
```
````

۲. کد درون‌خطی: `` `0.375` ``
۳. اسپن جهت‌دار: `<span dir="ltr">0.375</span>`

## جدول‌ها ستون‌هایشان جابه‌جا می‌شود

جدول را داخل بستهٔ جهت‌دار بگذارید. اگر باز هم بد بود، هر سلول عددی را در `<span dir="ltr">` بگذارید. در ابزار `rtl_view.py` این کار خودکار انجام می‌شود: سلولی که فقط عدد و علامت باشد، چپ‌به‌راست و وسط‌چین رندر می‌شود.

## فهرست گلوله‌ای در سمت چپ ظاهر می‌شود

نشانگر فهرست تابع جهت بلوک است. بستهٔ جهت‌دار این را هم درست می‌کند.

## تگ‌ها به‌صورت متن دیده می‌شوند

یعنی رندرکننده اچ‌تی‌ام‌ال را غیرفعال کرده است. آزمون سریع: یک پیام کوتاه بفرستید که فقط این باشد:

```html
<div dir="rtl">آزمون</div>
```

اگر واژهٔ «آزمون» بدون تگ دیده شد، اچ‌تی‌ام‌ال عبور می‌کند. اگر خود تگ دیده شد، این مسیر بسته است؛ به جای آن از نویسه‌های کنترلی استفاده کنید: RLI در آغاز جملهٔ حاوی لاتین و PDI در پایانش.

```text
⁧ضریب 0.375⁩ برای زیمنس
```

(در متن بالا، نویسهٔ نامرئی پیش از «ضریب» کد U+2067 و پس از «0.375» کد U+2069 است.)

## متن را به ورد بردم و نویسه‌های عجیب دیدم

RLM و RLI نامرئی‌اند ولی شمارش می‌شوند. پیش از چسباندن در ورد، پاکشان کنید:

```bash
python tools/rtl_wrap.py draft.md --strip-marks
```

## فونت مناسب فارسی

اگر فونت سیستم فاقد شکل‌های درست فارسی است، وزیرمتن یا ایران‌سنس نصب کنید. در فایل‌های اچ‌تی‌ام‌ال این کیت، وزیرمتن از شبکهٔ توزیع محتوا بارگذاری می‌شود و در نبود اینترنت به تاهوما برمی‌گردد.

## بررسی پیش از ارسال

```bash
python tools/rtl_lint.py draft.md
```

خروجی سه چیز را می‌گوید: بستهٔ جهت‌دار هست یا نه، کدام خطوط رشتهٔ لاتین درون‌خطی دارند، و کدام بلوک کد بدون برچسب زبان است.
